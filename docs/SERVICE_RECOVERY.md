# 初始化与服务恢复

适用于 v0.9.4。初始化链接、密码、运行配置和数据库日志可能包含敏感信息，不要公开粘贴；排障优先提供错误码和脱敏阶段。

## 首次设置

在该项目的真实 Codex 管理聊天内，通过已安装插件的入口依次执行：

```text
python <插件绝对路径>/scripts/run.py call management_open
python <插件绝对路径>/scripts/run.py call service_setup
```

第一步必须返回管理绑定成功，再打开第二步返回的 `setup_url`。凭据有效期十分钟，只能使用一次。打开页面的只读核验不会消费凭据，提交密码时仍会在事务中复验。普通首页不提供无凭据的密码设置表单；会客室不提供初始化入口。

| 提示 | 处理方式 |
| --- | --- |
| 缺少或尚未签发凭据 | 在管理聊天请求初始化链接 |
| 无效或被替换 | 使用最近一次签发的完整链接 |
| 已过期 | 重新请求链接 |
| 已完成或已使用 | 返回首页登录；不要重复设置 |
| 宿主核验超时或状态不明 | 检查 Codex 与当前项目聊天状态，核验成功前不会绑定管理聊天 |

不能手填其他聊天 ID、跳过项目核验或把缺凭据误当作密码错误。界面语言切换会重新载入页面；初始化时如果链接凭据已经从地址栏移除，重新打开原有效链接即可继续。

## 离线与重启

1. 在当前项目使用 `python <插件绝对路径>/scripts/run.py doctor` 检查服务。`ready: false` 才表示当前未确认就绪；网页登录失效本身不表示服务离线。
2. 在原管理聊天请求 `call service_resume`。保留 stderr 阶段输出与最终 stdout JSON，外部执行工具设置至少 150 秒等待。
3. 若外层超时或连接断开，结果可能尚未确认。先重新检查 doctor，再在原管理聊天查询 `call assistant_status`；不要直接重放管理操作。
4. 核对服务健康状态和控制结果后，再按需要明确启动平台。恢复服务不会自动启动角色。

| 阶段/错误 | 含义与下一步 |
| --- | --- |
| Python 启动前出现 `Requested registry access is not allowed` | 执行环境拒绝终端访问，插件尚未运行；在获准的项目终端使用同一官方入口。不要据此判断数据库损坏 |
| `execution_denied` / `runtime_launch_failed` | 子进程权限被拒绝或运行环境不可启动，检查执行权限或重新准备运行环境 |
| `service_start_busy` / `database_start_busy` | 另一请求持有启动锁，稍后查询状态 |
| `database_status` / `database_recovery` | 正在检查或由 PostgreSQL 执行恢复；不要清空数据或手删 PID 文件 |
| `service_start_failed` | 子进程在就绪前退出，查看本次启动阶段及退出码 |
| `service_start_timeout` | 未在启动预算内确认健康，后台可能仍在启动；先查状态 |
| `host_timeout` / `wrong_project` / `chat_archived` | 宿主身份或所属项目核验未通过，必须从正确的活动管理聊天调用 |
| `service_control_timeout` / `plugin_control_timeout` | 操作结果未确认，先查询状态，再决定是否重试 |

服务启动预算为 60 秒，控制 HTTP 为 40 秒，CLI 协作预算为 105 秒，插件子进程保护为 120 秒。数据库恢复子预算为 50 秒，宿主核验为 15 秒。内部预算在检查点及可超时等待处生效，操作系统或底层库若阻塞仍由外层子进程保护限制 CLI 等待；不能把超时解释为事务已回滚。

启动脱敏状态位于安装数据目录的 `runtime/service-startup.json`，仅本次子进程 PID 匹配的阶段才会被桥接入口采纳。阶段诊断不记录消息、密钥、聊天 ID 或完整文件路径。`runtime/service.log` 与数据库原始日志仅供本机核查，不宜直接发布。

本版已在隔离 Windows PostgreSQL 上验证非正常关闭后的恢复及已提交数据保留；这不证明任一现场异常退出的触发源。若再次退出，应保留退出时刻、退出码与阶段信息，关联宿主/系统事件继续调查。
