# v0.9.3 实施与验收记录

2026-10-27，依据 [已确认更新计划](V0.9.3-UPDATE-PLAN.md) 在 `codex/v0.9.3` 分支实施。十项更新已落地，本地自动回归、浏览器检查和构建验证通过。实际回复速度、部署者的 NapCat 登录及 B站现场恢复仍需手测；本记录不将合成环境验证写成真实平台验收。

## 关键行为与升级边界

- 所有手动额度调整立即生效，保留成功、处理中及结果不确定的占用。默认值只影响仍继承默认的对象；独立设置跨日保留。
- 每日用量按配置时区自然换日；跨日完成的发送在原预占日期结算。群聊时长从原开始时间计算，降低上限导致耗尽时结束参与，调高上限或恢复默认不会复活已结束的阶段。
- 旧私聊共享账本按加密发送记录中的精确对象归属迁移，并保留旧账本及迁移标记。缺记录或总量不一致时明确报错，不将历史计数清零或平均分配。
- 并发处理保留最终授权、账号、来源、额度、暂停和发送结果检查，不自动更换模型或降低推理档位。B站没有增加专项提速机制。
- 微信名称作为展示元数据，与身份及收件游标分离；改备注、昵称不重置已核验身份、授权或收件位置。只使用已核验对象的必要名称，不扩大联系人扫描范围。
- 公开成长恢复使用随包提供的中性默认内容，预览明确显示拟替换数据。旧状态归档；不可读的派生内容不重新标记为公开，也不恢复旧快照。预览绑定管理员会话，两分钟有效，状态或权限变化后必须重新预览，完成后 B站保持暂停。
- issue #5 的代码路径和一致性缺口已用隔离数据复现与修复，但没有读取现场私有数据库，不能断言现场全部历史失效均由同一原因引起。
- NapCat 托管使用真实进程句柄和 Windows Job 记录归属，持久化 PID 仅供诊断。连续启动、失败回滚、等待登录和停止均有覆盖；服务重启不自动恢复角色运行。
- 通用进程归属管理归入核心包，宿主保留兼容导入。QQ 独立包不再依赖未声明的宿主模块，独立包检查已加入 CI。

## 待手测的实际体验

1. 在部署后的 QQ、微信及本机会客室，保持实际所选模型和档位，先用普通短文本体验等待时间；原截图为 6.1 sol / low。图片、长历史回忆、网页阅读另行观察，不要求改善百分比或 P95 报告。
2. 用自己的 NapCat 启动路径验证没有实例时启动、已有实例复用、实际扫码登录、错误账号、暂停后的托管清理及外部实例保留。合成监听进程三次启停已通过，但不代替客户端的登录行为。
3. 在额度页选一个联系人和群，验证齿轮修改、恢复默认和保留已用量；按计划确认降低上限停止参与、已结束群阶段不因增加额度复活。
4. 若原有 B站成长状态仍失效，在暂停状态下进入“系统设置 → 公开成长恢复”，核对诊断和拟重建数据后确认，再明确启动，观察准备阶段、成长更新和下一周期是否连续完成。
5. 用实际备注、群名和较长名称查看主要页面，并切换两种语言。切换前保存尚未提交的表单；实际消息内容和通知语种应保持原有机制。
