# v0.9.4 初始化与服务恢复修复记录

2026-10-28。对应仓库 issue #7、#8，主包、核心、QQ、微信与插件发行版本统一为 0.9.4。

## 问题、修改及边界

| 问题 | 修复行为 |
| --- | --- |
| #7：没有初始化凭据的普通首页仍能提交密码 | 无凭据时隐藏并禁用表单；只有服务端核验通过的一次性链接才显示表单。缺少、未签发、无效、过期、已使用分别提示，提交前后均保留凭据与管理员状态校验。 |
| #7：管理入口核验等待不清晰 | 宿主核验优先查当前项目活动聊天，保留归档查询；核验总预算 15 秒，拒绝重复分页游标。超时核验不能继续绑定管理聊天。 |
| #8：服务启动与控制请求的等待叠加，外部超时后不知处于哪一阶段 | 启动改为按真实经过时间计算预算；区分启动锁、执行权限、进程退出、健康检查、宿主核验、控制请求及数据库恢复。错误响应保留脱敏阶段，进度写 stderr、最终 JSON 写 stdout。 |
| #8：Windows 服务离线后的恢复缺少证据和指引 | 保留 PostgreSQL 自身恢复机制，为锁、状态、恢复增加预算和阶段信息；增加官方恢复顺序、超时后先查状态、执行环境拒绝与应用错误的区分。 |
| 上一版远端许可检查失败 | 同步网页第三方许可副本与仓库原文，补齐系统字体说明。 |

认证、项目与归档核验仍然生效。恢复不自动启动平台，不修改用户模型或推理档位，不删除数据库或 PID 文件。长驻后台任务与启动诊断隔离，避免持续改写启动记录。诊断管道断开不影响正常操作。

服务启动 60 秒、控制 HTTP 40 秒、CLI 协作预算 105 秒、插件子进程保护 120 秒；外层工具建议至少 150 秒。内部预算在检查点及支持超时的等待处生效。超时与连接断开表示结果未确认，不能据此断言操作失败或事务已回滚。

现场 `0x40010004` 异常退出的触发进程仍未查明；首次约一分钟的超时缺少当时的阶段记录，不能声称已证明某个锁死根因。终端在 Python 启动前出现的注册表访问拒绝属于执行环境，应用无法捕获尚未启动时的错误。本版修复可复现的表单缺口和等待/诊断缺口，验证数据库异常关闭后的恢复，并为再次出现的现场故障留下可判断的阶段证据。

## 验证

测试使用隔离数据、合成账号与单独 PostgreSQL 实例；未启动真实平台或发送外部消息。真实宿主检查只读取当前聊天的项目和活动状态，不创建回合、不绑定管理员、不修改正式资料。

- 完整单元回归：807 项通过，证据 `.dev/v094/unit.xml`。
- 核心、PostgreSQL 与微信全量回归：1,800 项通过，2 项因缺少可选本地原生 DLL 跳过，无失败，证据 `.dev/v094/core-postgres-wechat.xml`。
- 最终新增恢复、发布、初始化和控制定向回归：38 项通过，证据 `.dev/v094/recovery-release-final.xml`。与全量用例存在重叠，不能相加作为独立用例总数。
- 中英文浏览器初始化：无链接不可提交、过期链接、有效链接启用、提交时已消费凭据、会客室无初始化入口全部通过。
- 既有浏览器回归：78 项布局、20 项几何及 9 项关于页检查通过；双语、额度编辑与恢复、成长重建交互无页面异常。证据位于 `.dev/v094/browser/`。
- Windows 隔离 PostgreSQL 经非正常关闭后，使用本版托管数据库入口恢复成功，恢复耗时约 5.55 秒，已提交的合成记录完整保留，随后清除测试表。证据 `.dev/v094/database-crash-recovery.json`。
- 真实宿主只读核验成功，耗时约 8.31 秒。该结果不代表所有设备的固定延迟或现场故障已经重现。证据 `.dev/v094/real-host-check.json`。
- 四个 wheel 构建通过；核心独立初始化、备份和恢复通过，QQ 在禁止导入宿主集成模块时仍可初始化。
- 代码规范与九处发行版本一致性检查通过。

未执行的两项分别为微信实验探针和原生发送的本机编译 DLL 检查，不计为通过；需要真实微信、QQ 或 B站账号的现场体验也不以合成测试替代。

## 发布与使用

纯净源码快照输出至 `.dev/releases/v0.9.4/`，包括 `repository/`、`source.zip` 与逐文件散列 `audit.json`。安装 wheel 位于 `.dev/v094/wheels/`。源码包排除 Git 历史、开发环境、数据库、密钥、登录资料、个人角色资料和本地截图，默认人物卡为空。

恢复步骤见 [初始化与服务恢复](SERVICE_RECOVERY.md)，网页手册提供独立中英文说明。更新仓库与发布包不会自动替换正在使用的已安装插件或迁移正式数据；部署升级后需要从正确项目的管理聊天进行现场确认。
