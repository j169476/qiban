# 栖伴 v0.9.4 测试版

本版修复首次初始化与服务恢复路径，主包、模块及插件统一为 `0.9.4`。

- #7：普通首页隐藏并禁用首次初始化表单；只有一次性凭据经过服务端核验后才能设置密码。缺少、未签发、失效、过期和已消费的凭据分别给出可操作提示；核验不消费凭据，提交时仍事务性复验。
- #7 / #8：宿主身份核验优先查询当前项目的活动聊天，归档查询继续保留；整个核验受时间预算约束，重复分页游标会明确拒绝。超时的核验不能继续绑定管理聊天。
- #8：服务启动改为按真实经过时间限制等待，区分启动锁等待、执行权限拒绝、进程退出、服务就绪和控制请求超时；插件入口、数据库恢复及服务控制提供脱敏阶段与耗时。服务端异常保留脱敏调用帧，不记录消息正文、凭据、聊天标识或完整路径。
- 保留控制 HTTP 的 40 秒预算；启动总预算 60 秒、CLI 协作预算 105 秒、插件子进程保护 120 秒，外部工具建议至少 150 秒。外层超时只表示结果未确认，先查状态，不直接重放操作。
- 首次初始化和重启继续保留真实宿主身份、同项目、归档状态及管理员认证；不自动启动角色，不清空数据库，不绕过权限恢复。

验证范围及现场故障的未确定部分见 [v0.9.4 修复记录](V0.9.4-FIXES.md)。

# 栖伴 v0.9.3 测试版

主包、核心、Codex 桥接、QQ / 微信独立连接器与插件统一为 `0.9.3`。

## 本版更新

- 回复流程：普通寒暄省去不必要的检索词扩展调用；不同会话最多并行处理两个，同一会话保留顺序；流式事件集中消费，空闲时仍快速检查撤销；自动备份的压缩与写盘不再阻塞收件循环。模型、推理档位和最终发送检查不变。
- 对象额度：每位联系人独立计算每日额度，每个群独立设置参与额度。账号设置作为默认值，卡片齿轮支持独立调整与恢复默认。手动调整立即生效并保留已用量；自然日按配置时区重置；群时长从原开始时间计算，结束阶段不会因调高上限恢复。
- QQ / issue #4：配置本机 NapCat 启动程序后，明确启动 QQ 时按需拉起并等待登录、核验账号；复用已有健康实例；停止后只清理本次拥有的进程组，保留外部实例。
- B站 / issue #5：区分公开成长来源登记缺失、来源变化、权限失效与完整性异常；修正公开关系日常更新与成长快照的一致性；管理页支持预览并以中性默认内容重建，旧状态归档，平台保持暂停。
- 网页中英文切换覆盖管理室、会客室、登录页和用户手册；浏览器独立保存偏好，首次匹配浏览器中英文语言，否则默认英文。角色回复、原内容和聊天通知不随界面语言改变。
- 全局文字层级、状态配色与布局更新；宣传文案移至独立品牌区域，常驻规则说明移入手册；后台状态自然语言化，名称为主、UID 为辅助信息，原始编码保留在技术详情。
- 继续使用系统字体和既有授权插画、图标，无新增字体或远程素材依赖。

自动回归及发布包审查记录见 [实施记录](V0.9.3-IMPLEMENTATION.md)。普通短文本实际回复速度由维护者手测；实机 NapCat 登录及退出也需使用部署者自己的配置确认。未将合成环境验证等同于真实平台验收。

# 栖伴 v0.9.1 测试版

Python 主包、核心、Codex 桥接、独立 QQ / 微信连接器与插件统一 `0.9.1`。尚未发布稳定版兼容承诺。

包含共享角色与记忆核心、加密 PostgreSQL 本地服务、管理网页与后台管理聊天，以及 B 站、微信、QQ 和本机会客室入口。微信和 QQ 使用统一的默认拒绝会话授权、私聊额度和群有限参与策略。连接器与核心分离，账号、收件游标和发送动作有各自核验边界。

本次公开整理移除开发交接文档、个人实测记录、人物卡和头像素材。初始化角色名称、描述、表达风格、兴趣和基础记忆全部留空，不包含外观与关系预设。合成检索数据保留在测试目录。

本轮统一对外版本为 v0.9.1（`0.9.1`）；v8.1、V8.2 是开发阶段迭代编号，不是发行版本。v1.0 正式版将在维护者完成人工长时运行和各功能验证后发布。

## v0.9.1 修复与调整

- 移除活动与休息时段限制及网页设置。平台显式启动后持续轮询，B 站收件、内容工作流和最终发送不再按小时阻断。旧 `active_hours` 字段兼容读取但不再生效；日额度仍按配置时区计数，发送间隔、授权、暂停和归档检查继续生效。
- 修复微信桥接构建失配、缺失或清单损坏导致网页出现 JSON 解析错误的问题。启动预检返回脱敏错误和修复指引，失败后保持暂停；其他非 JSON 响应显示 HTTP 状态及通用提示。
- 修复 QQ 首次连接和微信收件器尚未初始化时被误报为重连。控制台分别显示准备连接、等待重连、连接受阻、需重启客户端和发送待核实。
- QQ 平台卡片新增“打开 QQ 连接器”，与接入向导共用本机管理页地址，支持读取本地 NapCat 配置中的端口。链接在新窗口打开，不携带 Token，不启动平台。
- 旧版因时段限制暂缓且确定未发送的任务可重新评估；仍检查任务归属、有效期和重试次数，发送结果不确定的动作不自动重放。

## 2026-10-27 修订

- QQ、微信接入向导支持依赖复用、身份核验和追加多个私聊或群聊目标；旧微信配置迁移保留已核验的稳定 ID 和收件位置。授权名单可检索、分页和预览导入，明确确认后追加合并。
- 网页与管理聊天共用模型目录、全局默认和分平台覆盖设置；模型或推理档位不可用时明确报错。
- 修复 B站网页启动的管理身份校验，以及只读或额度耗尽时无法正常结束内容工作流的问题；受限测试运行保留目标范围与停止原因。
- 修复微信依赖准备、登录状态识别与发送排队问题。发送许可在完成排队和最终授权检查后签发，过期许可仍然拒绝，发送结果不确定时不自动重放。
- 浏览器登录校验任务对应的项目和数据目录，避免更新另一套安装；网页分别呈现登录会话过期、服务断线和平台等待重连。
- 守护进程恢复需要新心跳确认，服务恢复后各平台保持暂停；异常诊断仅记录有界调用位置和错误类型，不记录消息正文或局部变量。
- 故障通知始终跟随当前绑定的管理聊天，换绑后待发送通知使用新绑定；运行归属与管理聊天相同时仍通知一次。已发送和结果不确定的通知不重发。
- 会话消息序号迁移为 BIGINT，避免长会话的序号范围不足；独立 QQ、微信包的依赖范围与本次核心版本对齐。
- 发布导出排除本地开发交接、人工验收记录、运行配置、数据库及凭据；人物卡与基础记忆保持空白。

## 已知限制

- Windows 是当前本机服务安装和微信接入的目标环境；没有完成跨系统部署验收。
- 新安装需自行准备 PostgreSQL、平台账号与可用 Codex 宿主。QQ 桥接和微信原生构建不是一键安装。
- 微信受精确客户端指纹限制；支持多个已核验私聊和群聊，仍只支持受限文本发送，新增对象须分别核验和授权。
- QQ 协议端需使用者自行部署；不同桥接、客户端更新和多账号组合需实际验证。
- 群参与判断、话题结束和角色表达存在模型不确定性；额度与授权仍由程序强制检查。
- 已有自动化测试与有限实机验证不替代后续功能验收和长时运行。发布准备不会再自动发送验收消息。
