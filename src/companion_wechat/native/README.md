## 协议

- `XlnOpen`：绑定微信 PID / 创建时间、控制进程 PID / 创建时间、随机内存会话令牌、
  经过验证的小号身份、大号目标，以及可选的单个家庭群目标。
- `XlnPrepare`：检查目标和单行 UTF-8 文本，将严格递增序列的唯一待发请求放入内存。
- `XlnCommit`：逐字匹配准备内容，消费该序列，最多排入一次微信原生任务。
  任务执行前再次检查账号、控制进程存活、最小化状态、授权和 1.5 秒期限。
- `XlnCancel`：撤销当前尚未进入原生 builder 的任务；不承诺撤回已经发送的消息。
- `XlnStatus`：只返回计数、状态码和序列，不返回账号、文本或数据库密钥。
- `XlnClose`：撤销会话并清零待发请求和授权内容。DLL 固定保留至微信正常退出，
  避免回调返回时卸载代码；闲置时没有循环、线程或监听器。

微信模块只接受已审查的 `Weixin.dll` 文件大小、SHA-256、内存 PE 标记和账号对象链。
当前支持的指纹对应 4.1.15.13 和 4.1.15.56；更新后的其他版本必须重新审查。
仅版本字符串相同不足以放行。

加载和状态远程调用都有限时。线程超时后不释放其参数、不卸载 DLL、不重复提交；
该发送端停止后续动作，要求人工检查，必要时正常重启小号微信。
同一微信进程只允许一个存活的控制进程租约；接管失效租约仍须等待旧任务和回调全部结束。

## 离线构建与测试

在项目根目录运行：

```powershell
.\scripts\build_wechat_native.cmd
.\scripts\test_wechat_native.cmd
```

使用本机 MSVC x64、C++17、`/W4 /WX` 构建。产物和源码摘要清单位于
`.dev/wechat/native-module-build/`，不会加载到微信。
第二条命令将生产会话状态机接到模拟进程、窗口和时钟函数上测试，也不访问微信。
Python 测试位于 `tests_wechat/test_native_sender.py`；编译后的导出通过 PE 解析检查，
检查过程不会调用 `LoadLibrary`。

Python `NativeSenderGateway` 复用核心加密动作账本。原生完成回调与只读数据库中严格匹配的
新发送记录必须同时成立，动作才算成功。该成功表示本机已记录发送，不等于对方已读。
