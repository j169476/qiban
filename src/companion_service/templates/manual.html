开始使用额度与群聊资料与权限界面与模型记录与用量故障与恢复

开始使用

  1. 从 Codex 的 Qiban 管理入口打开初始化链接，设置本机密码。管理室用于配置，会客室用于聊天；网页会话分别登录。
  2. 在“平台与会话”中选择 QQ 或微信，检查现有配置，填写账号、连接地址及收发对象，保存后执行身份核验。检查配置和打开页面都不会启动角色。
  3. 按完整号码或内部 ID 查找已核验对象，核对账号、联系人或群后授予回复权限。导入与核验不等于授权；变更授权会暂停相应平台，随后需要明确启动。
  4. 在平台卡片设置本次时长、只读选项，再点击启动。时长留空表示不设本次运行截止时间。暂停会停止接收新任务并处理正在发送的结果。

QQ 连接器

卡片的“打开 QQ 连接器”可跳转本机 NapCat 管理页。希望随平台启动时，在接入设置填入可执行程序的绝对路径、工作目录、每行一个参数和等待时限；脚本需显式配置解释器。先完成连接器登录与账号核验，再建立消息连接。

已有且账号正确的连接器会被复用。停止时仅清理本次由 Qiban 创建并持有进程组句柄的连接器及子进程；外部启动的连接器、普通 QQ 客户端不受影响。旧 PID 记录不作为结束进程的依据。服务重启后平台保持暂停。

微信与 B站

微信需先完成已登录客户端的只读身份核验，只登记明确选定的账号和对象。客户端重启或原生桥接变化时，按状态提示重新准备或核验。B站需完成登录并检查凭证；成长来源故障与登录凭证故障分别处理。限定私信验收只接收指定账号、指定对象的新消息，且最多尝试一次外发。

额度与群聊

“额度与用量”分别展示本机限制、账户共享额度和 Qiban 已观测用量。联系人每日额度按“平台＋登录账号＋联系人”独立计算；群聊按每个群的参与阶段独立计算。

  1. 在对象卡片右下角点击齿轮，调整该对象的额度；“恢复账号默认”移除该对象的覆盖。
  2. 平台账号设置提供默认值。修改默认值立即影响仍继承默认的对象，已有独立设置的对象保持自己的值。
  3. 所有手动调整保存后立即生效，保留已成功、处理中和结果不确定的用量。降低后已用尽会阻止后续参与；提高额度不自动重发、不自动启动已暂停的平台。
  4. 每日额度按配置时区的自然日重置，手动设置本身跨日保留。跨日完成的发送计回原来预留额度的日期。设置修改不会从修改时刻重新计 24 小时。
  5. 群聊时长从原参与开始时刻计算；更改上限或时长不会重置已用回复数、决策数或开始时间。已结束或到期的阶段不因调高额度、恢复默认而重新开启，需再次正常唤起。

处理中的发送会占用额度；无法确定发送结果时继续保留占用，避免重复发送。旧共享私聊账本迁移时按精确收件对象的发送记录核对；无法核对会提示人工检查，不会清零或均分历史用量。

资料与权限

人物卡与基础记忆在确认可公开后共用。私人事实、原始对话、关系和派生资料仍按账号、会话与来源授权检查。更改名称仅影响展示，后台持续以唯一标识核验身份；名称缺失时显示中性占位及 UID。

资料工作台的结构化编辑器、技术详情、导出 YAML 保留原始字段和标记。导入先预览再保存；删除先检查影响。来源变化可能使依赖旧版本的内容失效，不能通过重新标为公开绕过检查。

界面与模型

页面顶部可一键切换中文与英文。首次按浏览器首个匹配的中英文偏好选择，均不匹配时默认英文；手动选择优先，并在刷新和重新打开后保留。同一浏览器同一主机的管理室、会客室、登录页和手册共用选择；其他浏览器或设备独立。语言切换会重新载入页面，请先保存正在编辑的表单。

界面语言仅控制管理显示和本手册，不翻译已有内容，不限制模型语言，也不改变角色回复或聊天自动通知。模型与推理档位仍由你选择；分平台覆盖优先于全局默认，保存影响下一次模型请求，当前请求保持原型号。

记录与用量

模型调用完成只说明该阶段结束，不表示平台消息已送达。请通过回复处理记录核对最终发送状态。“未标注阶段”表示旧记录未携带分类，不能推断为生成回复。检索词扩展记录的零耗时不等于模型生成没有耗时。

缓存输入包含在输入中，推理输出包含在输出中，不重复相加。未上报的用量显示“未知”，不能解释为免费或零消耗。账户共享额度来自宿主快照，过期或无法获取时会标明状态。

普通短文本是本版回复速度的主要手测场景，图片、长历史回忆、网页阅读分别观察。不同会话可有限并发，同一会话按顺序处理，最终权限、额度与发送检查持续生效。

故障与恢复

连接与运行

网页登录过期不表示服务断开，也不会自动停止平台；刷新后重新登录。页面刷新不会启动角色。宿主退出、聊天归档或服务重启后，依照状态提示明确恢复服务和平台。结果不确定的发送先核对实际收件，系统不会自动补发。

公开成长

  1. 先暂停 B站并等待当前任务退出。在“系统设置 → 公开成长恢复”点击检查。
  2. 核对具体来源诊断及拟重建内容。本版恢复使用随包中性默认值，不复制无法读取的旧派生内容。
  3. 确认重建后，旧状态会被归档留存，权限登记与新状态在同一事务内更新。预览两分钟内有效；资料或授权变化需重新预览。
  4. 重建不会自动启动 B站，也不会恢复已失效的旧快照；检查结果后明确启动。

备份

建立加密备份，并将加密恢复密钥和口令分开妥善保存。恢复资料需先预览覆盖范围并再次输入密码；恢复会覆盖当前资料，退出所有网页会话并撤销跨账号授权。接近应用备份容量上限时安排受保护的 PostgreSQL 备份。

A practical guide to connecting platforms and managing your companion. Applies to v0.9.3.

Getting started

  1. Open the initialization link from Qiban in Codex and set a local password. Use the management room for configuration and the lounge for conversation. Each surface has its own sign-in session.
  2. Under Platforms, select QQ or WeChat, inspect existing settings, enter the account, endpoints and recipients, then save and verify identity. Inspecting settings or opening a page does not start a platform.
  3. Search verified recipients by their complete number or internal ID. Check the account and recipient before granting reply permission. Importing or verifying a recipient does not grant permission. Authorization changes pause the affected platform; start it explicitly afterwards.
  4. Choose a duration and read-only option on the platform card, then start. An empty duration means no run deadline. Pausing stops admission of new work and allows in-progress sends to settle.

The QQ connector

The connector link opens the local NapCat management page. To launch it with the platform, configure the executable's absolute path, working directory, one argument per line, and readiness timeout. Scripts require an explicitly configured interpreter. Login and account verification precede the message connection.

A healthy connector with the expected account is reused. Stopping only cleans up the process group that Qiban created and still owns, including descendants. Externally launched connectors and ordinary QQ clients remain untouched. A stored PID is never authority to terminate a process. Platforms remain paused after a service restart.

WeChat and Bilibili

WeChat requires read-only verification of the signed-in client and explicitly selected accounts and recipients. Follow the status guidance after a client restart or native-bridge change. Bilibili login failures and growth-source failures have separate diagnostics. A limited direct-message test accepts new messages only from the specified account and recipient and attempts at most one external send.

Quotas and groups

Usage shows local limits, shared account allowances and usage observed by Qiban separately. Each contact has a daily quota keyed by platform, signed-in account and recipient. Each group has its own participation window.

  1. Use the gear at the bottom right of a recipient card to edit its quota. Restore account defaults removes its overrides.
  2. Account settings supply defaults. Editing them immediately affects recipients that inherit defaults; independent settings keep their own values.
  3. Every manual adjustment takes effect immediately and retains successful, in-progress and unconfirmed usage. Lowering an exhausted limit stops further participation. Raising a limit does not resend messages or start a paused platform.
  4. Daily counters reset at midnight in the configured timezone. Manual settings persist across days. A send that finishes after midnight settles against the day on which its quota was reserved. Editing a limit does not start a new 24-hour period.
  5. Group duration is measured from the original start time. Editing limits or duration preserves reply and decision counts. An ended or expired window is not reopened by raising limits or restoring defaults; normal activation is required.

In-progress sends reserve quota. Unconfirmed sends retain their reservation to prevent duplicates. Migration from the old shared direct-message ledger reconciles exact recipients against send records. Unreconciled history requires review; it is never silently cleared or divided among recipients.

Content and permissions

The persona and foundation memories are shared only after they are confirmed suitable for public use. Private facts, original conversations, relationships and derived records remain subject to account, conversation and source permissions. Display names do not change identity: the backend uses unique identifiers. Missing names use a neutral label with the UID alongside.

Structured editors, technical details and YAML exports retain original field names and identifiers. Preview imports and deletion impact before committing. Source changes can invalidate derived content; reclassifying it as public cannot bypass source checks.

Interface language and models

Use the language selector at the top of any page. The first visit follows the first supported Chinese or English browser preference, otherwise English. A manual choice takes priority and survives reopening. Management, lounge, sign-in and manual pages on the same host share that browser's choice; other browsers and devices remain independent. Switching language reloads the page: save edited forms first.

This setting changes management displays and this manual only. It does not translate existing content, restrict model language, or change character replies or automatic chat notifications. You remain free to choose the model and reasoning effort. Platform overrides take priority over global defaults; changes apply to the next model request.

Records and usage

A completed model stage does not confirm message delivery. Check reply records for the final send result. An unlabelled stage is an older record without classification, not evidence that it generated a reply. A zero-duration query expansion record does not mean model generation took no time.

Cached input is included in input tokens; reasoning output is included in output tokens. Do not add them twice. Unreported usage is unknown, not free or zero. Shared account allowances come from host snapshots and are marked stale or unavailable when appropriate.

Ordinary short text is the primary manual speed-check scenario. Observe images, long-history recall and web research separately. Different conversations may run with limited concurrency; each conversation stays ordered, and final permission, quota and send checks remain active.

Troubleshooting and recovery

Connections and runs

An expired web session does not mean the service is disconnected or stop platforms. Reload and sign in again. Refreshing a page never starts the character. Follow status guidance to explicitly resume the service and platforms after host exit, chat archival or service restart. Verify actual receipt before handling an unconfirmed send; it is never automatically replayed.

Public growth

  1. Pause Bilibili and wait for current work to finish. Open Settings → Public growth recovery and inspect the preview.
  2. Review the source diagnostic and proposed replacement. Recovery uses shipped neutral defaults; it does not copy unreadable derived content.
  3. Confirm the rebuild. The old state is archived and the new state and permission registration are updated in one transaction. Previews expire after two minutes; changed content or permissions require a fresh preview.
  4. Recovery does not start Bilibili or revive invalid old snapshots. Review the outcome and start explicitly.

Backups

Create encrypted backups and keep the encrypted recovery key and passphrase separately. Restore requires a scope preview and password confirmation; it replaces current data, ends web sessions and revokes cross-account grants. Arrange a protected PostgreSQL backup if data approaches the application backup limit.
