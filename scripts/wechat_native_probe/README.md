# 微信原生发送桥接：受限实验

这是独立于角色服务的单次能力实验。它不注册自动任务、不启动角色、不发送群消息，未接入生产自动回复。

原版完整桥接会向临时 JSON 写入收件人和正文，还包含收件 Hook、媒体、好友和群管理能力。因此这里仅保留文本发送需要的任务队列、字符串 ABI、完整构建指纹函数及三个导出：

| 导出 | 作用 |
| --- | --- |
| `XlnInspect` | 核验构建、当前登录账号、进程启动时间、目标窗口、最小化、前台窗口、固定探针格式；保存一次性请求至 RAM |
| `XlnSendOnce` | 最多调度一次发送；在微信任务队列执行时再次核验账号、窗口及 15 秒期限 |
| `XlnStatus` | 返回不含账号、正文和密钥的计数及完成状态 |

只接受 `XLN_NATIVE_PROBE_` 加 32 位随机十六进制串。Python 组合入口只从已有加密存储取 `owner_main` 绑定，没有任意目标或文本命令行参数。账号地址读取和系统导出定位参考上游，未导入或执行上游 Python 入口，未使用上游预编译 DLL。

## 构建和运行

使用本机 VS 18 BuildTools 的 x64 MSVC，`/MD /O2 /std:c++17 /W4 /WX`；`std::function<void()>` ABI 有编译时大小断言。

```powershell
scripts\wechat_native_probe\build.cmd
.venv\Scripts\python.exe -m scripts.wechat_native_probe --inspect
.venv\Scripts\python.exe -m scripts.wechat_native_probe --check-receiver
# window 是本轮观察到并由账号/PID 再核验的微信窗口句柄；重启后必须重新获取。
.venv\Scripts\python.exe -m scripts.wechat_native_probe --send-once --window <本轮窗口句柄>
```

仅在用户明确授权的实测中执行 `--send-once`。`--inspect` 和 `--check-receiver` 不加载发送桥接。`--diagnose-receipt` 只读取原有两条授权聊天的有界待收范围，输出固定探针的方向、时间差和正文哈希；不保存收件游标，也不能替代发送前的真实回执水位。

DLL 和构建清单位于 `.dev/wechat/native-probe-build/`。加载前检查源码签名、DLL SHA256 和恰好三个导出；指纹清单是本地构建一致性检查，不是对恶意本机文件篡改的签名认证。`vendor_extract.py` 只允许从工作区内干净、固定提交的上游克隆重新提取辅助函数和许可证。

## 进程、数据和退出边界

- 支持精确指纹的微信 `4.1.15.13`、`4.1.15.56`，未知构建拒绝原生调用。`4.1.15.56` 的发送、账号读取及数据库只读连接需要单独实测记录。
- 先按已有绑定的稳定账号 ID 选择唯一微信进程，校验启动时间。重启后的 PID 只在本次内存配置中覆盖，不依赖窗口标题或昵称，也不重写私人配置文件。
- 源密钥仅在已有 SQLCipher 子进程 RAM 中使用。桥接本身不接触数据库密钥，不解密数据库，不写消息日志。不会生成整库明文缓存。OS 换页、崩溃转储及 Python/库内部复制不属于可以承诺全部擦除的范围。
- 原生桥接不调用前台激活、键鼠、剪贴板 API，不安装收件 Hook。窗口准备由用户或 Sky 完成，原生桥接只读窗口状态。
- 发送前捕获真实数据库最大行号水位。回执只核对同一来源、同一目标和本次文本的唯一新自发记录。数据库确认不代表收件人已读；原生完成回调也不单独作为发送成功依据。
- 本机短测发现服务端消息时间约比本机起始时间早 1.23 秒。实验入口在真实水位捕获后等待 3 秒再发送新随机探针；不修改系统时间，不倒填水位时间，不放宽旧消息时间窗。这是本次能力实验的准备步骤，不是通用时钟同步方案。正式适配器需要单独处理时钟偏差。
- 20 ms 轮询记录最小化和前台状态；它是有限频率的观察，不能排除短于采样间隔的瞬态变化。
- 超时或不确定结果不重发，不终止远程线程，不释放可能仍被线程使用的参数。失败保持不确定，不伪装成拒绝。
- 提交时将这个 22 KiB 左右的 DLL 固定到当前微信进程生命周期，防止回调/析构刚归零时卸载代码。完成后它没有持续任务、Hook、监听端口或后台发送循环；一次性标记阻止再次提交。正常退出该小号微信后由系统清理，下一次独立实验需要正常重启小号。提交前失败可以在远程线程结束后正常卸载。
- 无论结果如何，探针关闭已有数据库 worker，释放自己的句柄和可以安全释放的参数。不会自动重启微信。

## 测试和正式接入边界

离线测试位于 `tests_wechat/test_native_probe.py`，覆盖固定目标、消息格式、未知 PE/版本、双读账号切换、超时保留参数、禁止二次提交、独立回调与回执证据、窗口变化及确认先于回调的时序。

旧角色核心及数据库收件接口保持原样；数据库版本白名单增加 `4.1.15.56`，仍要求 SQLCipher 页认证，已有受限查询、RAM 密钥、游标和断线逻辑不变。

正式接入时需要单独的原生发送适配器，复用核心授权、幂等动作账本和 DB 回执。不能伪造当前 UI 发送器要求的空草稿/窗口证明。常驻多次发送、跨重启恢复、失联后的不确定动作处理、撤销和退出协议仍需实现与审查；本实验没有把单次 DLL 变成长期机器人。群聊未验收，长时实测由用户后续完成。
