# 共用人物设定与交流记忆（0.8.0）

PostgreSQL 保存唯一运行人物卡。用户明确登记为共用的 `persona` 及其 `foundation_memories` 清单，在核心私聊、B站公开回复和显式网页任务中完整加载。固定设定独立于普通记忆召回预算；不再因公开场景换一张默认卡。未登记的旧资料仍按原权限隔离，不能自行公开。

基础人物卡与基础记忆仅由用户在已登录管理网页维护。“共用人物卡与基础记忆”区域可以查看、添加、移出条目；编辑沿用资料工作台的版本检查。移出条目停止召回，保留历史用于恢复。YAML 只是受控导入、导出格式，编辑已退役目录不会修改正式数据库。固定内容缺失、权限撤销或超出完整加载上限时报告问题，不从旧缓存补造或替换人物卡。

自动学习继续积累交流经历、知识、兴趣、情绪、好感与人物印象。它不能改写基础人物卡或基础记忆；用户口头表达的新偏好先作为实际交流处理，需要改变固定设定时由用户在管理网页修改。固定设定、示例对白与参考立绘不属于已发生的共同经历，也不计为反思的新经历。

用户自己的实际交流与其他用户一样建立身份档案，并按当前账号、会话、公开范围、来源和可撤销授权读取。“主人”、好感、昵称及跨平台硬关联均不授予私人资料读取权限。公开设定可自然用于公共交流，私人交流仍不能进入未授权的公开回应。

`relationship_baseline` 表示用户明确设定的关系底色，`observed_relationship` 与好感分记录真实积累。零互动不抹去设定，也不能虚构交往次数。情绪、真实分歧和最新表达仍影响相处。

`visual_identity` 保存形象描述与参考图哈希。服务在实际生成角色配图时按任务检查和读取参考图；路径或图片说明不代表已看过图片。Codex 启停入口不读取这些资料代替角色回复，也不恢复旧的 `state_load`、`memory_get/write` 流程。

本机私人对话在显式启动、非只读且会客室登录有效时自动整理。`companion.memory_maintenance` 控制开关；默认累计未完整压缩的记录达到 `conversation_summary_after=40` 条后触发，保留 `conversation_keep_recent=12` 条最近原文。每次最多处理 50 条，长消息分片；每次整理最短间隔 30 秒，与回复共用每日模型额度，新消息优先。关闭平台后台浏览不会关闭已启动的本机对话整理。

摘要只属于当前会话，原文不删除。来源修改、删除、权限撤销、退出登录、归档及暂停均参与复核；未完成结果不能提交。重启仍保持暂停，显式启动并有有效角色登录后，从已提交摘要和原文续接。失败按 60/120/240 秒退避，连续三次失败沿用单次管理通知并暂停。可在管理网页查看整理状态，不在 Codex 管理聊天输出私聊摘要。

私密互动还通过同一次回复模型调用维护 `interaction_growth`：按平台账号、说话者和会话保存独立的情绪、兴趣、待反思经历及日常反思，全部继承完整来源。兴趣变化需引用当前消息原文，情绪只能引用当前事件，且受单次与每日限幅。到达反思时间且经历足够时，下一次私密回复才可反思；不会在暂停或无人交谈时额外唤醒模型。来源被修改或撤销时，旧成长不再读取；它不更新共用人物卡、固定基础记忆或公开成长。
