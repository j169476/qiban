# 独立核心与跨平台身份（0.5）

模型调用由 `companion_codex` 适配，人物、记忆、关系、存储和身份规则在 `companion_core`；B站 API、登录和内容采集仍在 `bili_assistant`。当前只接通 B站，QQ、微信尚无真实连接器。安装或迁移不会启动角色。

## 自动判别与人工修正

- 本人发言明确声明另一平台账号时，核心记录 `suspected` 疑似关联。昵称、头像、兴趣相似不能确认身份。
- 后续两个账号各自的实际入站消息具有具体、可对应的对话证据时，由 Codex 评估并提出 `correspondence`，核心核验消息来源、版本、原文引用和双方主体后升级为 `hard`。
- `hard` 是可撤销的推断，不是平台实名认证或登录凭证，不授予主人或管理权限。
- 原始记录保留平台与主体来源。人物映像汇集各账号的印象和好感明细，不相加好感、不抹掉不同平台的记录；证据过期或争议会停止共享关联。撤销不删历史。
- 跨平台私聊原文仅用于独立身份评估，普通回复不自动获得另一平台的私聊原文。

## 工具

- `identity_status`：管理聊天查看 YAML 记录与实际生效状态。
- `identity_revoke(link_id, expected_version, reason)`：撤销并锁定错误关联；自动流程不能重新合并。
- `person_profile(platform, user_id, scope?)`：查看来源明确的人物映像，管理和角色聊天均可使用。
- `core_migrate`：管理聊天在角色暂停时幂等补建旧 B站主体与事件映射；不改人物卡、好感分值或已有动作记录。升级前做完整备份。
- 角色入口用 `identity_context` 读取证据，用 `identity_propose` 提交提议；后台会在实际收件时自动执行同样的判断，不需要另一套模型服务。

`identity_links/*.yaml` 是关联事实源，SQLite 为可重建的索引；仍可本地编辑。手动裁决可设置 `manual: true`、`locked: true` 并填写原因；结构需通过校验。未经人工明确裁决，不把模型推断改成手动确认。数据库中的动作与关系去重账本不能删除。

新平台的连接器需声明收件、读取和可执行能力，并在实际发送前调用核心传入的停止检查。平台账号、会话和动作去重键相互隔离；动作结果不确定时保留 `uncertain`，不自动重发。
